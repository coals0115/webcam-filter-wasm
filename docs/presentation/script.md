## 2. 프로젝트 개요 [손아영]

> 저희는 WebAssembly와 C++로 웹 브라우저에서 실시간으로 웹캠 영상에 필터를 적용했습니다. JavaScript만으로는 복잡한 픽셀 연산을 실시간으로 처리하기 어렵기에 C++로 작성된 이미지 처리 알고리즘을 WebAssembly로 컴파일했습니다.

### 시연 + 기능 소개

> 저희는 총 6가지 필터 기능을 구현했습니다.
>
> 세피아 필터부터 X-Ray 필터, 4사분면으로 나뉜 거울 필터, 흑백 필터, 사진 파일을 선택 후 색상을 선택하면 해당 색상 부분은 사진 이미지로 보이게 되는 크로마키 필터와 마지막으로 열화상 필터가 있습니다.
>
> 필터 버튼 아래에서는 프레임당 처리 시간과 초당 프레임 수를 확인할 수 있는데, 성능 지표는 초록색, 파란색, 노란색, 빨간색 색상 순서대로 우수에서 주의를 나타냅니다.

## 5. 코드 설명

### 손아영 - 세피아, X-Ray 필터 [손아영]

> 다음은, 각 팀원별로 담당한 필터 코드를 간단히 설명드리겠습니다.
>
> 우선, 세피아 필터는 이미지 데이터의 메모리 주소를 받아, 픽셀 단위로 반복 처리합니다. 각 픽셀의 RGB 값을 읽고, 정수 연산으로 세피아 공식을 사용해 새로운 색상 값을 계산합니다. 최종 결과는 클램핑 후 8비트 데이터로 변환해 원래 메모리 위치에 덮어씁니다.
>
> X-Ray 필터는 명암 반전과 대비 증강을 조합하여 X-Ray 투과 효과를 데이터에 적용합니다. 모든 픽셀을 반전한 뒤, 픽셀 밝기의 차이를 극대화합니다. 그리고, 계산 결과가 범위를 벗어나지 않도록 0~255 사이로 클램핑하며, 이 값을 메모리에 최종 저장합니다.

### 강성준 - 크로마키, 열화상 필터 [강성준]

> 크로마키입니다. 이 기술의 핵심은 카메라에 비친 현재 색상이 사용자가 지정한 기준 색상과 얼마나 가까운지를 수학적으로 판단하는 것입니다. 이를 위해 RGB 3차원 공간의 거리 공식을 활용했는데요. 여기서 중요한 점은 성능입니다. 연산 비용이 비싼 '제곱근' 함수를 사용하는 대신, 오차 범위와 거리의 '제곱값'을 직접 비교하는 방식으로 알고리즘을 최적화하여 픽셀 처리 속도를 비약적으로 높였습니다.
>
> 다음 열화상 필터는 실제 온도가 아닌 영상의 '밝기'를 색상으로 시각화하여 열화상 카메라 같은 효과를 내는 기능입니다. 구현 과정에서는 먼저 우리 눈에 가장 민감한 녹색 채널에 가중치를 더 주는 방식으로 밝기 값을 구하되, 비트 연산을 사용하여 처리 속도를 최적화했습니다. 그 후, 계산된 밝기에 따라 어두운 곳은 파란색, 밝은 곳은 빨간색과 흰색으로 변하도록 6단계의 그라데이션을 매핑하여 리얼한 열화상 느낌을 연출했습니다.

### 방채민 - JS↔WASM 연동 [방채민]

> 저는 JavaScript와 WASM 간의 메모리 연동을 담당했습니다.
>
> README의 다이어그램처럼, Canvas에서 getImageData로 픽셀을 추출하고, WASM 힙에 버퍼를 할당한 뒤, HEAPU8.set으로 데이터를 복사합니다. C++ 필터가 처리를 마치면 HEAPU8.subarray로 결과를 읽어와서 Canvas에 다시 렌더링합니다.

## 6. 어려웠던 점과 해결 방법 [방채민]

> 저희 팀이 겪은 어려움과 해결 방법을 간단히 말씀드리겠습니다.
>
> 먼저, JS와 WASM 간 경계를 넘나드는 비용이 크다는 것을 조사를 통해 알게 되었습니다. 픽셀마다 호출하면 프레임당 30만 회 이상 호출이 발생하는데, 이를 고려하여 HEAPU8.set과 subarray로 데이터를 일괄 복사하는 방식을 적용했습니다.
>
> 또한, 매 프레임마다 버퍼를 새로 할당하면 가비지 컬렉션 부담이 커진다는 것을 알게 되어, 앱 시작 시 버퍼를 한 번만 할당하고 재사용하는 방식을 적용했습니다.

## 7. 가산점 항목 [방채민]

> 가산점 항목으로 추가 기능 구현에 대해 말씀드리겠습니다.
>
> 첫째, 기본 요구사항 외에 총 6가지 필터를 구현했습니다. 흑백, 세피아, X-Ray, 거울, 크로마키, 열화상 필터입니다.
>
> 둘째, 크로마키 필터는 단순한 필터가 아닌 완전한 시스템으로 구현했습니다. 사용자가 원하는 색상을 직접 선택할 수 있고, 허용 범위를 10에서 150까지 슬라이더로 조절할 수 있으며, 배경으로 사용할 이미지 파일을 업로드하는 기능까지 지원합니다.
>
> 셋째, 실시간 성능 모니터링 대시보드를 추가했습니다. 프레임당 처리 시간과 FPS를 실시간으로 표시하고, 초록색, 파란색, 노란색, 빨간색으로 성능 상태를 시각화하여 사용자가 현재 성능을 직관적으로 파악할 수 있도록 했습니다.

## 8. Latency 측정 [방채민]

> 마지막으로 성능 측정 결과입니다. 640×480 해상도에서 50회 평균으로 테스트한 결과, 모든 필터에서 C++/WASM이 JavaScript보다 1.2배에서 2.9배까지 빠른 것을 확인했습니다.
>
> 특히 세피아 필터가 2.9배로 가장 큰 성능 향상을 보였고, 이를 통해 WebAssembly가 연산 집약적인 이미지 처리 작업에서 실제로 성능상 이점이 있다는 것을 증명할 수 있었습니다.
